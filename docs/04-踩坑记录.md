# 04 - 踩坑记录

## 坑 1 — 输入 0 V 却读出 100~300 码、峰峰 830 码

- **现象**
  - 万用表量电位器抽头对 GND：接近 0 V。
  - GUI 显示原始码在约 100~300 之间，单次 64 点过采样峰峰值达 830 码（≈669 mV）。
  - 均值以约 10 Hz 在 ~155 与 ~263 间交替（疑似 50 Hz 工频被 20 Hz 采样混叠）。
- **定位过程**
  1. 固件均值与 min/max 自洽（mean≈263 时 min=120、max=1181），排除求和/格式错误。
  2. 串口原始行确认 20 Hz 稳定输出，排除串口丢包。
  3. 3 ms 窗口内出现 1 V 级尖峰，且直流分量仅 0.2 V，符合**高源阻抗拾取工频**的特征。
  4. 若抽头确实在 GND 端，源阻抗应接近 0，不应出现此现象 → 怀疑电位器未真正供电、
     抽头接触不良，或电位器被接成两端可变电阻（rheostat）而非分压器。
- **根因**
  - 尚未最终确认。当前首要嫌疑：电位器 3V3/GND 未接通（抽头经电阻悬空），
    或抽头端子接触不良；其次为缺少 100 nF 采样电容 + 长线拾噪。
- **解决（待验证）**
  1. 万用表确认电位器两端分别为 3.3 V / 0 V。
  2. 转到中点，确认抽头 ≈1.65 V。
  3. 抽头对 GND 并联 100 nF（靠近 GPIO3）。
  4. 若仍异常，换 GPIO0/1/2/4 交叉验证，排除引脚损坏。
- **关联文档**：[02-硬件与引脚分析](02-硬件与引脚分析.md)、[03-开发进度日志](03-开发进度日志.md)

### 坑 1 后续（2026-10-30 第二轮）— 已具备定位工具

- **混叠解释**：固件以 20 Hz 输出均值，若输入叠加 50 Hz 工频，则
  `|50 − 2×20| = 10 Hz`，正好对应观测到的“均值以约 10 Hz 在 155/263 间摆动”。
  单窗口 64 点背靠背采样仅约 3 ms，窗内看到的是 50 Hz 的瞬时值，因此峰峰值可达数百码。
- **诊断步骤**：
  1. 上电后先不接/接好电位器，GUI 按 `F9`（或串口发 `B 4096`）。
  2. 看「噪声频谱」窗口：主频是否在 50 Hz、50 Hz 幅度是否远大于 100 Hz。
  3. 抽头对 GND 加 100 nF 后重抓，50 Hz 幅度应明显下降。
  4. 用 `C 0/1/2/4` 换通道重抓，排除单引脚问题。
- **判据**：
  - 50 Hz 幅度 ≫ 噪声底 → 工频拾取（高阻/长线/缺滤波）。
  - 频谱平坦且峰峰仍大 → 接触不良/电源纹波/其他干扰。
  - 短接抽头到 GND 后仍跳 → 更可能是引脚或板级问题。
- **待填**：上板后的实际频谱截图与 50 Hz 幅度。（待硬件）

### 坑 1 上板复测（2026-10-30，已接入硬件）

- 条件：GPIO3 / 12 dB / 64 次 / 20 Hz；电位器抽头接 GPIO3；未加 100 nF。
- D 行（120 点，6 s）：raw 均值 2178.35，cal 1617.1 mV，lin 1755.4 mV；
  窗内峰峰均值 31.9 码（25.7 mV），最大 112 码；σ 均值 5.57 码（4.49 mV）。
- `B 8192`：等效 7415.6 Hz、1.10 s；峰峰 130 码（104.8 mV），σ 5.97 码（4.81 mV）；
  **50 Hz 幅度 0.095 mV、100 Hz 0.063 mV**，主频落在噪声 bin（约 1 kHz，0.17 mV）。
- 结论：
  - 首轮“0 V 却跳 100~300 码、峰峰 830 码”**未复现**，工频拾取假设不成立。
  - 当前噪声为宽带噪声 + 约 0.1% 的偶发尖峰（个别 +75/−55 码），与接线/接触或 ADC 自身
    瞬态有关，待加 100 nF、换通道后对比。
  - 万用表真值 1603 mV：校准误差 +14.1 mV（0.88%），线性误差 +152.4 mV（9.51%），
    当前点校准明显更接近真值。
  - 数据：[data/20261030_baseline_gpio3_D.csv](../data/20261030_baseline_gpio3_D.csv)、
    [burst8192](../data/20261030_baseline_gpio3_burst8192.csv)、
    [标定点](../data/20261030_points.csv)。
  - 关联：[08-性能参数](08-性能参数.md)

## 坑 3 — USB Serial/JTAG 命令无响应，主机写入阻塞（已解决）

- **现象**
  - 固件能持续输出 `D` 行，但发送 `H` / `S` / `B` 没有任何 `#HELP` / `#CFG` / `#BURST` 响应。
  - 上位机 `serial.write()` 最终抛 `SerialTimeoutException`，`out_waiting` 累积到 1280 字节。
- **定位过程**
  1. 串口输出正常，排除 USB 枚举/波特率问题。
  2. `H` 写入偶尔成功（2 字节），但设备始终不回应 → 不是主机写失败，而是设备没人读。
  3. 查 IDF `usb_serial_jtag_vfs.c`：主机未连接/重新枚举时 `read()` 返回 −1，
     `fgets(stdin)` 立即返回 `NULL`。
  4. 原 `cmd_task` 用 `while (fgets(...) != NULL)`，任务在启动早期直接退出；
     之后 RX FIFO 无人清空，主机写入填满后阻塞。
- **根因**
  - 命令任务把“暂时未连接”的 EOF 当成“输入结束”，启动后永久退出。
- **解决**
  1. 固件改为 `fgetc` + `clearerr` + 50 ms 重试，任务常驻。
  2. GUI 打开串口后设置 `dtr=False / rts=False`，避免 DTR/RTS 影响 USB Serial/JTAG 写入。
  3. `SerialReader` 改为“块读 + 按行拆分”，`B 4096` 抓取从约 25 s 降到 <1 s。
- **验证**
  - `H` 返回 8 行 `#HELP`；`S` 返回 `#CFG`；`B 8192` 在 1.3 s 内完成并正确解析。
  - GUI 实机连接 + `F9` 抓取 2048 点成功。
- **关联文档**：[06-设计说明](06-设计说明.md)、[07-使用说明](07-使用说明.md)

## 坑 2 — GUI 采样率显示成 18 万 Hz（已解决）

- **现象**：演示模式下采样率显示 186309 Hz。
- **根因**：串口线程一次把积压的多行塞进队列，主线程连续处理时用
  `time.monotonic()` 计算相邻行间隔，得到微秒级 dt。
- **解决**：改用固件时间戳 `t_ms` 计算最近 50 点的平均周期，显示恢复 20.0 Hz。

## 坑 4 — 点“记录当前点”/F2 没有反应（已解决）

- **现象**
  - 输入万用表真值后点按钮或按 F2，状态栏停在“等待稳定… 已连续 0/3”，
    等很久也不记录，状态栏不更新。
- **定位过程**
  1. 用 xvfb 跑真实串口复现，11 s 后 `points=0`，状态仍是第一次的“0/3”。
  2. 打印 Tk 回调异常，发现 `UnboundLocalError: stable_hits`。
  3. `check()` 内对 `stable_hits` 赋值，Python 把它当局部变量；`stable_hits + 1`
     在赋值前读取，第一次回调就抛异常，后续 `after()` 没有注册，等待链直接死掉。
- **根因**
  - 嵌套回调缺少 `nonlocal stable_hits`，不是串口/校准/阈值问题。
- **解决**
  1. `check()` 内加 `nonlocal stable_hits`。
  2. 等待稳定超时（4 s）改为**仍然记录**，并提示“稳定超时，已按当前值记录”。
  3. 等待期间再按 F2/再点按钮 = 立即记录，不强制等稳定。
  4. 稳定阈值默认调到 50 mV（无 100 nF 时更符合实测噪声）。
- **验证**
  - 真机：阈值 200 mV 时约 0.4 s 自动记录；阈值 10 mV 时 4 s 超时后记录；
    等待中第二次 F2 立即记录。三种路径均生成标定点。

## 坑 5 — 右侧面板随数据跳动（已解决）

- **现象**
  - 实时读数刷新时，右侧宽度/位置来回跳，左侧绘图区跟着变宽变窄。
- **根因**
  - “当前读数”的数值标签没有固定宽度，文本长度随数字变化 → 请求宽度变化；
  - 右侧 frame 允许子控件反向决定宽度（grid propagation），于是整列宽度跟着变。
- **解决**
  1. 数值标签 `width=20`、`anchor="w"`，文本长度不再影响布局。
  2. 右侧 frame 固定 `width=480` 并 `grid_propagate(False)`，列 `minsize=480`。
  3. 峰峰值/σ 文案缩短，避免超宽。
  4. 窗口高度 980，树表区域不再被压到 2 行。
- **验证**
  - 连续 3 次采样（1 s / 2.5 s / 4 s）打印右侧控件尺寸，宽度/高度完全一致。

## 坑 6 — 12 dB 档并不覆盖 0~3.3 V，约 2.89 V 已饱和（已确认）

- **现象**
  - 291 点全量程扫描中，真值升到约 2.89 V 后 raw 固定在 4095 不再增加；
  - 校准值钳在约 2940 mV，线性值钳在 3300 mV；
  - 继续升到 3.31 V，两个换算值都不变。
- **数据**
  - 饱和点 36 个，真值 2890~3313 mV；
  - 饱和区校准平台 2937.8~2940.0 mV，线性平台 3297.0~3300.0 mV；
  - raw<4090 的可用范围上限约 2871 mV。
- **根因**
  - 12 dB 档的实际可测上限约 2.9 V（不是标称的 3.3 V）；超过后 ADC 输出满码。
  - `raw×3300/4095` 在满码时仍报 3300 mV，会把饱和“伪装成”正常读数。
- **解决/建议**
  1. 3.3 V 输入前先用 **1:2 电阻分压**（并加 100 nF），让 ADC 看到 ≤1.65 V。
  2. 分析时必须排除 `raw ≥ 4090` 的点，否则 max/INL 会被饱和平台主导；
     `host/analyze.py` 与报告已自动处理。
  3. 不要把“线性换算在 3.3 V 附近误差变小”当成优点，那只是饱和平台恰好接近 3300。
- **后续（2026-10-30）**：抽头对 GND 加 **100 nF** 后，1.65 V 处 σ 从 30.8 mV 降到
  **1.05 mV**，峰峰值从 250 mV 降到 **7.3 mV**。噪声问题基本解决；此前的高噪声主要是
  高阻输入 + 长引线 + 无采样电容导致的宽带/脉冲拾取，不是 ADC 本身。
- **关联**：[08-性能参数](08-性能参数.md)、[09-实验结论与建议](09-实验结论与建议.md)

## 坑 7 — 真值输错/电位器位置不对，污染整份统计（已解决）

- **现象**
  - 31 点扫描导出后，报告 max 误差突然变成 **3300 mV**，RMS 842 mV；
  - 明细里最后两点：真值 3000/3300 mV，但 raw 只有 0.09/0.30。
- **根因**
  - 这两点是在电位器处于 0 V 附近时输入的 3000/3300（可能想写 3.000/3.300 V）；
  - 它们既不饱和、也不是有效点，却进入了线性度统计，把 max/RMS/拟合全部带偏。
- **解决**
  1. `adc_core.split_invalid()`：`|线性换算 − 真值| > 1000 mV` 判定为异常点，
     自动排除并单列；
  2. GUI 记录前检查：
     - 真值与当前线性换算相差 >1000 mV → 弹窗确认；
     - raw 已饱和但真值 <2.8 V → 弹窗确认；
  3. `analyze.py` 控制台同样打印异常点并排除，绘图只用有效点。
- **阈值依据**
  - 正常点的线性误差最大约 400 mV（12 dB 满量程附近），1000 mV 不会误伤有效点。
- **验证**
  - 同一份 33 点导出：修正前 max 3300 mV；修正后自动排除 2 点，
    0.1~2.7 V 结果为 max 12.6 mV / RMS 6.73 mV。
- **关联**：[09-实验结论与建议](09-实验结论与建议.md)、[08-性能参数](08-性能参数.md)
